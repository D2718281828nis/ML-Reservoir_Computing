# Reservoir Computing Explainer

An interactive page about feed-forward neural networks against reservoir computing for time-series forecasting:

1. **Two approaches to learning from past observations.** Where the memory lives (a window or a recurrent state) and what is trained (every weight or only the readout): a 2 × 2 map of FFN, ELM, NG-RC, RNN and ESN. Then the two hyperparameters of a reservoir: the leak rate α on a leaky-integrated signal, and the spectral radius ρ as the eigenvalues of W on the complex plane, rescaled live, with the decay of a disturbance ‖Wᵏv‖ against ρᵏ.
2. **The forward pass of a single forecast.** Both networks compute the same forecast, step by step, in the manner of [Transformer Explainer](https://poloclub.github.io/transformer-explainer/): one continuous data flow where every vector is a 1-D heatmap and a band is as wide as the vector it carries, expanded views of each part's math with live numbers (an FFN hidden unit, the FFN output, one reservoir neuron's update, the ESN readout), Step/Play, examples, live ρ, α and λ, and a guided tour. Then the loop unrolled in time (four steps of the same 100 neurons; on Step the columns slide, so x(t) visibly becomes x(t−1), with a ledger of one neuron's reads and writes), and the reservoir as an interactive directed graph (100 neurons, 1,000 links, force layout): hover for a neuron's incoming and outgoing links, and watch one change, a nudge to one neuron or one changed input, echo along the links and fade.
3. **Feed-forward networks.** An MLP on a window of Mackey–Glass, trained live with Adam; its first-layer weights move as it learns, and a short window cannot hold the memory the series needs.
4. **Reservoir computing.** Inside a 100-neuron echo state network: the echo state property (two runs from different starts merge, or don't), the roles of ρ, α and the input gain, and Jaeger's memory-capacity test against a window.
5. **Comparative evaluation.** Linear AR, ELM, ESN and FFN on one task against the wall clock; the ELM separates "readout-only training" from "recurrence".
6. **Forecasting real-world time series.** A lab on daily electricity demand (Spain), an ECG and Mackey–Glass, with chronological splits, baselines (persistence, same day last week) and NRMSE by horizon; then closed-loop free runs.
7. **Next-generation reservoir computing (NG-RC).** Next-generation reservoir computing: a feature counter, and NG-RC against an ESN on Lorenz-63, with valid time in Lyapunov times and ablations.
8. **Conclusions** and the accompanying notebooks.

## How it works

- **Everything trains in the browser.** `js/nn.js` has a small dense network with backprop and Adam (the FFN), and ridge regression through Gram matrices and Cholesky, so one pass over the data serves many λ. `js/models.js` has the reservoir (sparse random W, spectral radius by power iteration), the ELM, NG-RC features and the metrics. `js/core.js` runs every experiment without touching the DOM, so Node can run it too.
- **Data.** Mackey–Glass and Lorenz-63 are integrated with RK4 in `js/data.js`. The two real series come from `../dataset/` through `tools/build_assets.py` into `assets/series.json` (41 KB): the daily mean load of Spain's grid in GW, and the ECG averaged from 1 kHz to 250 Hz.
- **Two languages.** `index.html` (English) and `ru/index.html` (Russian) hold the prose. Strings generated by the scripts come from `js/i18n.js`, which picks the language from `<html lang>`.
- **No build step, no framework.** `js/app.js` boots the page; `js/sec-*.js` render the sections (`sec-flow.js` and `sec-graph.js` are part 2); `js/charts.js` and `js/util.js` hold the drawing helpers. Formulas use KaTeX from a CDN. The CSS repeats the design tokens of the [Autoencoder Explainer](https://github.com/D2718281828nis/ML-Transformers/tree/main/explainer/autoencoders) instead of importing them, so the pages can change independently. Series colors are fixed per model: ESN blue, FFN orange, NG-RC aqua, ELM yellow, truth ink, baselines gray.

## Run locally

```bash
cd explainer
python3 -m http.server 8000   # then open http://localhost:8000/
```

The page has to be served over HTTP (ES modules and `fetch` don't work from `file://`).

## Rebuild the data

```bash
python explainer/tools/build_assets.py   # numpy + pandas, a few seconds
```

## Verify

```bash
node explainer/tools/check.mjs
```

This runs the page's JavaScript in Node and compares it with numpy results stored in `assets/checks.json`: both integrators, an ESN's states,
readout and predictions, NG-RC feature vectors and readout, a multi-output ridge solve, the power-iteration spectral radius against numpy's
eigenvalues, the FFN's backprop against finite differences, and that every number shown in part 2 (the flow view's steps, the readout terms, the echo of one change) is the models' own computation.

## Deploy

`.github/workflows/pages.yml` publishes this folder to GitHub Pages on every push to `master` that touches `explainer/`.
One-time setup: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
